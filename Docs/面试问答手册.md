## Q2：游戏的架构是怎么设计的？（必问）

### 整体架构图

```
Input Layer（输入层）
    │ PlayerInput / InputManager
    ▼
Data Layer（数据配置层）
    │ FighterData / GameSettings / StageData（ScriptableObject）
    ▼
Core Layer（核心层）
    │ GameManager（单例） / ObjectPooler（单例）
    ▼
Character Layer（角色层）
    │ FighterController + FighterStateMachine
    ▼
Combat Layer（战斗层）
    │ Hitbox / Hurtbox / DamageSystem（静态）
    ▼
Managers Layer（管理层）
    │ CameraManager / MatchManager
    ▼
UI Layer（表现层）
    │ HUD / 选人界面 / 结算界面
```

### 为什么这样分层？

| 理由 | 说明 |
|------|------|
| 关注点分离 | 每层只做自己的事，输入不管渲染，战斗不管摄像机 |
| 可测试性 | DamageSystem 是纯静态类，不依赖 Unity，可以单独测击飞公式 |
| 可扩展性 | 加新角色只需配 FighterData SO 资产，不改代码 |
| 可维护性 | 每层替换/升级不影响其他层（如换输入系统只改 Input 层） |

**不好的设计对比：** 如果把伤害计算写在 FighterController 里，每次调公式都要拿到 MonoBehaviour 引用，测试时要挂载到 GameObject 上，非常麻烦。现在 DamageSystem 是静态类，传入参数直接算，干净。

## Q3：状态机是怎么设计的？（必问，格斗游戏核心）

### 状态枚举（13 个状态）

```csharp
public enum FighterState
{
    Idle,        // 地面待机——默认状态，可做任何操作
    Run,         // 地面移动——左右移动时
    Jump,        // 跳跃上升——起跳后到最高点前
    Fall,        // 自由下落——最高点后到落地前
    Attack,      // 攻击中——播放攻击动画期间，行为受限
    Hit,         // 受击硬直——被攻击命中的小硬直
    Stun,        // 眩晕——大硬直，不能操作
    Knockback,   // 击飞飞行——被强力攻击击飞，空中翻滚
    Shield,      // 防御——举盾状态，减伤但消耗护盾耐久
    ShieldStun,  // 防御硬直——盾被攻击后的小硬直
    Grab,        // 抓取——抓取对手成功后的状态
    Grabbed,     // 被抓取——被对手抓住，可挣扎
    Dead,        // 死亡——出界或被淘汰
    FreeMove,    // 自由移动——击飞后速度降低到一定程度，可空中受控但还不能攻击
}
```

### 关键设计点

**1. CanTransitionTo 校验规则：**

| 当前状态 | 允许转换到 |
|---------|-----------|
| Dead | 只能到 Idle（重生） |
| Attack → Attack | 允许（连击取消） |
| Knockback | Fall / Dead / Idle / Hit |
| Hit / Stun | Idle / Fall / Knockback / Dead |
| Shield | Idle / ShieldStun / Grab |
| 其他 | 默认允许 |

```csharp
public bool CanTransitionTo(FighterState target)
{
    if (CurrentState == FighterState.Dead && target != FighterState.Idle)
        return false;
    if (CurrentState == FighterState.Attack && target == FighterState.Attack)
        return true;  // 连击取消
    if (CurrentState == FighterState.Knockback)
        return target == FighterState.Fall || target == FighterState.Dead
            || target == FighterState.Idle || target == FighterState.Hit;
    if (CurrentState == FighterState.Hit || CurrentState == FighterState.Stun)
        return target == FighterState.Idle || target == FighterState.Fall
            || target == FighterState.Knockback || target == FighterState.Dead;
    if (CurrentState == FighterState.Shield)
        return target == FighterState.Idle || target == FighterState.ShieldStun
            || target == FighterState.Grab;
    return true;
}
```

**2. 三个辅助方法：**

```csharp
// 角色是否在空中？（用于空中攻击/空中闪避判断）
public bool IsInAir() { ... }

// 角色能否主动操作？（用于攻击/跳跃/防御判断）
public bool CanAct() {
    return CurrentState == Idle || Run || Jump || Fall || FreeMove;
}

// 角色是否可被攻击？
public bool IsVulnerable() {
    return CurrentState != Shield && CurrentState != Dead
        && CurrentState != Grab && CurrentState != Grabbed;
}
```

**面试追问：状态机为什么不用 ScriptableObject 配置？**
→ 格斗游戏状态转换规则固定，硬编码效率高、可控性强。SO 配置增加复杂度且没必要——大乱斗 clone 的状态转换逻辑不会频繁变化。

## Q4：击飞公式怎么算的？（面试亮点）

### 核心公式（基于大乱斗通用公式逆向工程）

```csharp
public static float CalculateKnockbackVelocity(
    AttackData attack, float targetDamage, float targetWeight)
{
    float dmg = Mathf.Max(0f, targetDamage);

    float baseKB = attack.knockbackBase;          // 基础击飞值
    float weightFactor = 100f / Mathf.Max(1f, targetWeight);  // 体重系数
    float growthFactor = attack.knockbackGrowth / 100f;       // 成长系数

    // 伤害加成：伤害越高击飞越远
    float bonusKB = (dmg * 0.1f) + (dmg * attack.knockbackGrowth * 0.05f);

    // 最终速度
    float knockbackSpeed = (baseKB + bonusKB) * weightFactor * 1.4f + 18f;
    knockbackSpeed *= growthFactor;

    return Mathf.Max(0f, knockbackSpeed);
}
```

### 公式的设计意图

| 变量 | 影响 | 设计目的 |
|------|------|---------|
| baseKB | 基础值 | 每种攻击的基础推力（Smash >> Jab） |
| bonusKB | 目标伤害越高→击飞越远 | 翻盘机制：残血更容易被击杀 |
| weightFactor | 体重越大→越难击飞 | 角色差异化（轻 vs 重） |
| knockbackGrowth | 成长系数 | 角色特色（有的角色低伤害弱、高伤害猛） |
| +18 | 保底速度 | 低伤害时也能打飞，防止手感太黏 |

### 击飞方向计算

```csharp
public static Vector2 CalculateKnockbackDirection(
    AttackData attack, Vector2 hitDirection)
{
    float angleRad = attack.knockbackAngle * Mathf.Deg2Rad;
    return new Vector2(
        hitDirection.x * Mathf.Cos(angleRad),  // 水平分量
        Mathf.Sin(angleRad)                     // 垂直分量
    ).normalized;
}
```

- **0°** = 水平击飞
- **90°** = 垂直向上击飞
- **45°** = Sakurai 角度（斜上方）

### 受击硬直时间（Hitstun）

```csharp
// 击飞速度越快 → 硬直越长
public static float CalculateHitstun(float knockbackSpeed)
{
    return Mathf.Max(0.05f, knockbackSpeed * 0.01f + 0.1f);
}
```

## Q5：Hitbox 和 Hurtbox 怎么设计的？（碰撞检测）

### 概念

| 组件 | 角色 | 行为 | 工作方式 |
|------|------|------|---------|
| **Hitbox** | 攻击方 | 主动检测 | 挂在角色手脚上，由 Animation Event 控制激活/关闭 |
| **Hurtbox** | 受击方 | 被动被检测 | 挂在角色身体上，始终是 Trigger |

### Hitbox（攻击判定框）

```csharp
// 由 Animation Event 在动画特定帧调用
public void Activate() { collider.enabled = true; }
public void Deactivate() { collider.enabled = false; }

// 命中检测
private void OnTriggerEnter2D(Collider2D other)
{
    Hurtbox hurtbox = other.GetComponent<Hurtbox>();
    if (hurtbox != null && hurtbox.owner != owner)
    {
        hurtbox.owner.ApplyDamage(attackData, owner);
        StartCoroutine(HitstopRoutine());  // 打击暂停
    }
}
```

### 攻击动画三段式

```
[前摇 startup] → [判定帧 active] → [后摇 recovery]
  按键按下         Hitbox激活        Hitbox关闭
  不能做其他操作   可命中对手        回到待机
```

帧数据在 AttackData 中配置：`startupTime / activeTime / recoveryTime`

### 为什么要分离 Hitbox 和 Hurtbox？

1. **解耦：** 攻击方只管打出去，受击方只管被打，互相不知道细节
2. **灵活：** 角色可以有多个 Hurtbox（头/躯干/手脚），未来可做部位伤害差异
3. **复用：** Hitbox 和 Hurtbox 都是通用脚本，挂到任何角色子物体上就能工作

### Hitstop（打击暂停）—— 格斗游戏手感的核心

```csharp
private IEnumerator HitstopRoutine()
{
    Time.timeScale = 0f;  // 冻结游戏时间
    float duration = attackData.hitstopDuration * hitstopScale;
    yield return new WaitForSecondsRealtime(duration);  // 用真实时间等待！
    Time.timeScale = 1f;  // 恢复
}
```

**注意：** 必须用 `WaitForSecondsRealtime`，不能用 `WaitForSeconds`。
原因：`Time.timeScale = 0` 时 `WaitForSeconds` 不会计时，协程永远不会恢复。
`WaitForSecondsRealtime` 不受 timeScale 影响。

### 使用 ScriptableObject 的好处

| 优势 | 说明 |
|------|------|
| 不写代码调数值 | 策划/自己直接在 Inspector 改，不用碰代码 |
| 数据复用 | 多个预制体可共用同一份 SO |
| 引用混编 | SO 可以直接引用 Prefab/AudioClip/Sprite（JSON 做不到） |
| 版本控制 | 每个资产是独立 .asset 文件，git diff 能看数值变化 |

SO 是 Unity 原生资源，可以直接引用其他 Unity 资源（Prefab、AudioClip、Sprite），这是 JSON 做不到的。读取时直接反序列化，不需要 I/O 解析，性能更好。缺点是不能跨平台/跨引擎使用，JSON 可以。

## Q7：对象池怎么实现的？（性能优化必问）

### 实现原理

```csharp
public class ObjectPooler : MonoBehaviour
{
    private Dictionary<string, Queue<GameObject>> poolDictionary = new();

    // 预创建
    public void CreatePool(GameObject prefab, int initialSize)
    {
        Queue<GameObject> pool = new();
        for (int i = 0; i < initialSize; i++)
        {
            GameObject obj = Instantiate(prefab, transform);
            obj.SetActive(false);  // 预创建的对象隐藏
            pool.Enqueue(obj);
        }
        poolDictionary.Add(prefab.name, pool);
    }

    // 取出
    public GameObject Spawn(GameObject prefab, Vector3 position, Quaternion rotation)
    {
        if (!poolDictionary.ContainsKey(prefab.name))
            CreatePool(prefab, 5);  // 自动创建

        Queue<GameObject> pool = poolDictionary[prefab.name];
        if (pool.Count == 0)
            pool.Enqueue(Instantiate(prefab, transform));  // 自动扩容

        GameObject obj = pool.Dequeue();
        obj.transform.position = position;
        obj.transform.rotation = rotation;
        obj.SetActive(true);
        pool.Enqueue(obj);  // 放回队尾（但 SetActive 控制可见性）
        return obj;
    }

    // 归还
    public void Despawn(GameObject obj, float delay = 0f)
    {
        if (delay > 0f)
            StartCoroutine(DespawnAfterDelay(obj, delay));
        else
            obj.SetActive(false);  // 只是隐藏，下次复用
    }
}
```

### 面试追问

**Q：池子里对象是移除还是隐藏？**
→ 只是 SetActive(false)，保留引用。下次 Spawn 直接从队列取，不需要 Instantiate（重操作）和 Destroy（触发 GC）。这就是对象池提升性能的核心原理。

**Q：Spawn 时队列空了怎么办？**
→ 自动扩容：Instantiate 一个新的，放进队列再取出。保证不会因为池空就报错。

**Q：为什么用 Queue 而不是 List？**
→ Queue 是先进先出，被回收的对象先被复用，符合"局部性原理"——刚用过的对象大概率很快又被用到（比如连续发射子弹），CPU 缓存命中率更高。

## Q8：摄像机系统怎么实现多目标跟踪？

```csharp
[RequireComponent(typeof(Camera))]
public class CameraManager : MonoBehaviour
{
    void LateUpdate()
    {
        // 1. 计算所有存活玩家的中心位置
        Vector3 center = CalculateCenter(activePlayers);

        // 2. 计算玩家分散程度（最远两名玩家的距离）
        float spread = CalculateSpread(activePlayers);

        // 3. 将分散距离映射到缩放值
        float targetZoom = Mathf.Lerp(minZoom, maxZoom,
            Mathf.InverseLerp(0f, 30f, spread));

        // 4. 平滑缩放
        currentZoom = Mathf.SmoothDamp(currentZoom, targetZoom,
            ref zoomVelocity, zoomSmoothTime);

        // 5. 限制在舞台边界内
        targetPosition.x = Mathf.Clamp(targetPosition.x, boundsMin.x, boundsMax.x);

        // 6. 平滑移动
        transform.position = Vector3.SmoothDamp(transform.position,
            targetPosition, ref moveVelocity, moveSmoothTime);
    }
}
```

### 为什么用 LateUpdate？

→ Update 里玩家先移动和攻击，LateUpdate 才更新摄像机，确保看到的是玩家最新位置。如果在 Update 更新，可能玩家还没移动完摄像机就动了，出现残影/抖动。

### 为什么用 SmoothDamp？

→ 直接赋值的摄像机是刚性的，跟着玩家瞬间移动会抖动。SmoothDamp 带阻尼，跟随有延迟但平滑。参数 `moveSmoothTime` 控制响应速度。

### InverseLerp + Lerp 的巧妙用法

```
玩家分散距离 (0~30)  ──InverseLerp──→  0~1  ──Lerp──→  缩放值 (8~20)
```

把两个不同范围的值线性映射，比 if-else 分支优雅得多。

### 上下文攻击选择（大乱斗风格）

```csharp
private AttackData GetContextualAttack()
{
    if (isInAir) {
        if (MoveInput.y > 0.5f) return aerialUp;
        if (MoveInput.y < -0.5f) return aerialDown;
        if (MoveInput.x > 0.5f) return aerialForward;
        if (MoveInput.x < -0.5f) return aerialBack;
        return aerialNeutral;
    }
    // 地面
    if (MoveInput.y > 0.5f) return tiltUp;
    if (MoveInput.y < -0.5f) return tiltDown;
    if (Mathf.Abs(MoveInput.x) > 0.5f) return tiltSide;
    return jab1;  // 不推方向 → 轻击
}
```

### 面试追问：输入缓冲怎么处理？

→ 当前版本是简化的，按下攻击键时如果角色在硬直中，输入会丢失。真实格斗游戏需要输入缓冲队列——存近 N 帧（如 6 帧）的输入历史，硬直结束后按队列执行。可以用环形缓冲区（`InputBuffer[60]`）实现。

## Q10：比赛流程怎么管理的？

```csharp
private IEnumerator MatchFlow()
{
    // 阶段1：开局倒计时 3 秒
    for (int i = 3; i > 0; i--)
    {
        Debug.Log($"Countdown: {i}");
        yield return new WaitForSeconds(1f);
    }

    // 阶段2：比赛进行
    IsMatchActive = true;
    while (IsMatchActive)
    {
        MatchTimeRemaining -= Time.deltaTime;

        // 时间制
        if (settings.matchMode == Time && MatchTimeRemaining <= 0f)
            EndMatch();

        // 命数制
        if (settings.matchMode == Stock)
        {
            var alive = activePlayers.FindAll(p => p.State != Dead);
            if (alive.Count <= 1)
                EndMatch(alive.Count == 1 ? alive[0].playerID : -1);
        }
        yield return null;
    }
}
```

### 为什么用协程而不是 Update + bool？

→ 协程把流程写成顺序结构，代码可读性高。倒计时、延迟等操作天然适合协程。但核心战斗用状态机——协程不能处理复杂的嵌套状态转换。**协程管流程，状态机管行为。**

## Q11：平台格斗游戏特有的技术挑战

## Q12：单例模式和类的职责划分

### 全局单例（跨场景不销毁）

```csharp
public class GameManager : MonoBehaviour
{
    public static GameManager Instance { get; private set; }

    void Awake()
    {
        if (Instance != null && Instance != this)
        {
            Destroy(gameObject);  // 防重复
            return;
        }
        Instance = this;
        DontDestroyOnLoad(gameObject);  // 跨场景不销毁
    }
}
```

| 单例类 | 持有数据 | 作用 |
|--------|---------|------|
| GameManager | GameSettings + 玩家列表 | 全局状态管理 |
| ObjectPooler | 池化对象字典 | 全局对象复用 |

### 场景内实例（每个场景独立）

| 类 | 为什么不是单例 |
|----|--------------|
| MatchManager | 每个战斗场景有自己的比赛规则和计时器 |
| CameraManager | 每个场景有不同的边界和摄像机配置 |
| InputManager | 每个玩家有自己的输入配置，挂载在玩家角色上 |

**面试追问：为什么不用所有类都是单例？**
→ 单例是全局状态，滥用导致耦合。MatchManager 和 CameraManager 是场景级别的，每个场景可能有不同的配置，不适合全局单例。InputManager 是每个玩家独立一份，更不能单例。

## Q13：Animator 怎么和代码状态机同步？

FighterController 每帧通过 UpdateAnimation() 向 Animator 写参数：

```csharp
void UpdateAnimation()
{
    animator.SetFloat("Speed", Mathf.Abs(velocity.x));       // 移动速度→走路/跑步 blend
    animator.SetBool("IsGrounded", IsGrounded);              // 是否在地面→地面/空中切换
    animator.SetFloat("VerticalSpeed", velocity.y);          // 垂直速度→跳跃/下落动画
    animator.SetFloat("Damage", CurrentDamage);              // 伤害值→受击表情变化
    animator.SetInteger("State", (int)StateMachine.CurrentState); // 当前状态→大状态切换
}
```

**注意：** Animator 和 FighterStateMachine 是两层独立的状态机。
- **代码层状态机**（FighterStateMachine）→ 控制逻辑：能不能攻击、能不能移动
- **表现层状态机**（Animator Controller）→ 控制动画：播放哪个动画片段

两者通过参数同步，各自独立运行。

## Q14：FighterController 的 Update/FixedUpdate 分工

```csharp
// Update：每帧执行，处理逻辑更新
void Update()
{
    UpdateGroundDetection();  // 地面检测（OverlapCircle）
    UpdateTimers();           // 攻击计时器、无敌计时器、护盾消耗/恢复
    UpdateGravity();          // 重力加速度（空中时 velocity.y += gravity * dt）
    UpdateMovement();         // 水平移动 + 状态切换
    UpdateAnimation();        // 同步参数到 Animator
}

// FixedUpdate：固定时间步长，处理物理
void FixedUpdate()
{
    if (isInKnockback)
        rb.velocity = knockbackVelocity;  // 击飞状态：直接设置击飞速度
    else
        rb.velocity = velocity;           // 正常状态：设置移动速度
}
```

**为什么分离 Update 和 FixedUpdate？**
- Update 帧率不固定（60fps 时每帧 16ms，掉帧时可能 33ms），不适合物理
- FixedUpdate 固定间隔（默认 0.02s = 50 次/秒），物理计算稳定
- 如果物理在 Update 里做，帧率波动会导致物理表现不一致（跳得忽高忽低）

## Q15：这个项目还可以怎么优化？（面试送分题）

### 1. 内存/GC 优化

| 问题 | 优化方案 |
|------|---------|
| Update 每帧 OverlapCircle 做地面检测 | 缓存检测结果 + 每 3 帧检测一次 |
| 对象池自动扩容有 Instantiate | 预创建足够数量，运行时避免 Instantiate |
| 字符串拼接（Debug.Log） | 条件编译 `#if UNITY_EDITOR` 包裹 |
| LINQ 在 MatchManager 中使用 FindAll | 改用 for 循环遍历 |

### 2. 架构完善

- **输入缓冲队列：** 把玩家输入存近 6 帧，解决"输入瞬间角色还在硬直"的问题
- **连段系统：** 实现 AttackData.cancelIntoAttacks 数组，形成 Jab1→Jab2→Jab3 连段链
- **动画事件驱动：** 用 Animation Event 精确控制 Hitbox 激活时机，匹配攻击帧数据

### 3. 战斗系统补全

| 功能 | 说明 |
|------|------|
| **DI（Directional Influence）** | 被击飞时玩家通过摇杆影响飞行方向，增加操作深度 |
| **Tech（受身）** | 碰墙/碰地前按防御键→受身免硬直 |
| **Shield Grab** | 防御中按抓取→盾抓 |
| **Edge Guard** | 悬崖边攻防博弈 |

### 4. 网络同步（如果面试问到格斗游戏的网络方案）

格斗游戏对网络要求极高，通常用 **回滚网络（Rollback Netcode）：**
- 不等服务器确认，先执行输入再回滚修正
- 不要求确定性计算（帧同步要求所有客户端同步计算结果）
- 实现方案：保存每帧快照 → 收到服务器确认后回滚到正确位置 → 重放未确认输入
- 代表游戏：街霸 6、GGPO 中间件

## Q16：角色数据 AttackData 的 18 种攻击

攻击体系（大乱斗标准）：

```
地面攻击：
  Jab 1/2/3       ← 轻击三连（连段）
  Tilt 上/横/下   ← 强攻击（推摇杆+攻击）
  Smash 上/横/下  ← 蓄力攻击（大击飞）

空中攻击：
  Neutral Air     ← 空N（不推方向）
  Forward/Back Air ← 空前/空后
  Up/Down Air     ← 空上/空下

必杀技：
  Neutral/Side/Up/Down Special

抓投：
  Grab → Throw Forward/Back/Up/Down
```

每个 AttackData 包含：

| 字段 | 说明 | 示例值 |
|------|------|--------|
| damage | 伤害 | 3~20 |
| knockbackAngle | 击飞角度 | 0~90° |
| knockbackBase | 基础击飞 | 10~80 |
| knockbackGrowth | 成长系数 | 20~100 |
| startupTime | 前摇（秒） | 0.05~0.3 |
| activeTime | 判定持续（秒） | 0.05~0.15 |
| recoveryTime | 后摇（秒） | 0.1~0.4 |
| hitstopDuration | 打击暂停（秒） | 0.05~0.15 |
