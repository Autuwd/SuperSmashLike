# 局域网联机扩展方案

> 本文档为 SuperSmashLike 项目设计未来的局域网（LAN）多人联机扩展方案。
> 覆盖：方案选型、架构设计、同步策略、代码改动清单、实施路线图。
> 当前状态：单机版代码已完成，本文档为"将来做"的蓝图。

---

## 一、方案速览

| 项目 | 决定 |
|------|------|
| **网络库** | Unity Netcode for GameObjects (v2.x) + Unity Transport |
| **拓扑结构** | Listen Server（Host = P1 的机器，同时跑服务器+客户端） |
| **同步策略** | **Input Sync（输入同步）**：Client 只发输入，Host 跑权威模拟，广播结果 |
| **传输协议** | UDP（Unity Transport 封装） |
| **LAN 发现** | UDP 广播（自定义 NetworkDiscovery） |
| **最大玩家** | 4 人（同局域网） |
| **估算工时** | ~10 天（单人），含调试 |

---

## 二、为什么选这个方案

### 2.1 技术选型对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **Unity Netcode** | 官方维护、轻量、与 Unity 2022.3 兼容、Netcode 2.x 已稳定 | 文档偏少、部分功能还在迭代 | ✅ **推荐** |
| Mirror | 成熟、文档好、社区大 | 第三方、架构偏重（Room Manager 等用不上） | ⚠️ 备选 |
| Photon Fusion | 自带 rollback、延迟优化好 | **付费**、闭源、毕业设计没必要 | ❌ |
| 纯 UDP 手写 | 完全可控 | 工程量巨大（序列化/重传/连接管理/同步全部手写） | ❌ |
| Steamworks P2P | 自带 NAT 穿透 | 强依赖 Steam、开发调试繁琐 | ❌ |

### 2.2 为什么 Input Sync 而不是 State Sync

| | Input Sync（本方案） | State Sync |
|--|---------------------|------------|
| **原理** | Client 只发输入，Host 跑全量模拟 | Host 跑逻辑，把结果状态广播给 Client |
| **通信量** | 极小（~8 bytes/帧/玩家） | 较大（~60 bytes/帧/玩家） |
| **一致性** | **天然一致**（所有 Host 决定结果） | 需要做冲突解决 |
| **反作弊** | 好（Host 权威） | 一般 |
| **适用场景** | 格斗游戏、RTS | FPS、赛车 |

LAN 延迟 <1ms，Input Sync 的延迟问题不存在，一致性优势突出。

### 2.3 拓扑：Listen Server  vs  Dedicated Server

| | Listen Server（本方案） | Dedicated Server |
|--|------------------------|------------------|
| **硬件需求** | 1 台玩家机器即可 | 需要额外一台电脑跑服务端 |
| **实现复杂度** | 低（Host 同时是本地玩家） | 高（需要处理无头服务端） |
| **公平性** | Host 有 ~0ms 延迟优势 | 所有人延迟公平 |
| **适用场景** | LAN 聚会（毕业设计） | 互联网对战 |

LAN 场景下 Host 的延迟优势可以忽略，选 Listen Server 省一台机器。

### 4.2 核心原则：Server Authority（服务器权威）

**一句话规则：一切游戏逻辑的最终决定权在 Host。**

| 行为 | 谁决定 | Client 怎么做 |
|------|--------|-------------|
| 角色位置 | **Host**（物理引擎跑） | 收到状态后插值显示 |
| 伤害计算 | **Host**（DamageSystem） | 收到伤害值后更新 HUD |
| 攻击命中 | **Host**（Hitbox 碰撞检测） | 收到状态后播放受击动画 |
| 击飞轨迹 | **Host**（物理引擎跑） | 收到速度后插值 |
| 击杀/死亡 | **Host**（BlastZone 检测） | 收到状态后播放死亡动画 |
| 比赛结束 | **Host**（MatchManager） | 收到通知后切换场景 |

**Client 不跑物理、不跑碰撞检测、不跑游戏逻辑。Client 只做三件事：**
1. 采集本地输入 → 发给 Host
2. 收到 Host 状态 → 插值平滑
3. 渲染（动画/特效/UI）

### 4.3 数据流详解

#### 每帧网络数据流

```
Client (P2) 的每一帧：
  1. 采集输入 → 打包 PlayerInputData (8 bytes)
  2. SendInputServerRpc() → Host

Host 的每一个 FixedUpdate (60fps)：
  1. 收集所有输入（本地+远程）
  2. 按顺序执行所有 FighterController_Server.FixedUpdate()
  3. 打包所有 FighterStateData → BroadcastStateClientRpc() → 所有 Client

Client (P2) 收到状态后：
  1. 将状态存入 StateBuffer（保留最近 3 帧用于插值）
  2. 渲染层从 StateBuffer 读取插值后的位置/状态
  3. 本地动画、特效正常播放
```

#### 消息类型定义

| 消息 | 方向 | 频率 | 优先级 | 可靠性 |
|------|------|------|--------|--------|
| `PlayerInputData` | Client → Host | 每帧 | 最高 | 非可靠（最新覆盖旧） |
| `FighterStateData` | Host → Client | 每帧 | 高 | 非可靠（最新覆盖旧） |
| `GameEvent_PlayerJoined` | Host → Client | 按需 | 高 | **可靠** |
| `GameEvent_MatchStart` | Host → Client | 按需 | 高 | **可靠** |
| `GameEvent_MatchEnd` | Host → Client | 按需 | 高 | **可靠** |
| `GameEvent_Respawn` | Host → Client | 按需 | 中 | 非可靠 |
| `GameEvent_Hitstop` | Host → Client | 按需 | 中 | 非可靠 |
| `NetworkDiscovery_Request` | Client → Broadcast | 扫描时 | 低 | 非可靠 |
| `NetworkDiscovery_Response` | Host → Client | 响应 | 低 | 非可靠 |

**为什么输入和状态不要求可靠传输？**
因为每帧都有新数据覆盖旧的。丢失一帧输入=那一帧用旧输入，下一帧自动修正。
如果强求可靠，丢包重传会导致延迟堆积，反而不如直接跳过。

### 4.4 数据包结构

```csharp
// === Client → Host：玩家输入（每帧发送） ===
// 大小：8 bytes / 帧 / 玩家
public struct PlayerInputData : INetworkSerializable
{
    public Vector2 moveInput;      // 4 bytes (2 × short)
    public ushort buttons;         // 2 bytes (位掩码)
    // bit 0: JumpPressed
    // bit 1: AttackPressed
    // bit 2: SpecialPressed
    // bit 3: ShieldHeld
    // bit 4: GrabPressed
    // bit 5: TauntPressed
    // bit 6-15: 预留
    
    public void NetworkSerialize<T>(BufferSerializer<T> serializer) where T : IReaderWriter
    {
        serializer.SerializeValue(ref moveInput);
        serializer.SerializeValue(ref buttons);
    }
}

// === Host → Client：斗士状态（每帧广播） ===
// 大小：~56 bytes / 帧 / 斗士 × 4人 = ~224 bytes / 帧 = ~13 KB/s
public struct FighterStateData : INetworkSerializable
{
    public Vector2 position;       // 8 bytes (2 × float)
    public Vector2 velocity;       // 8 bytes
    public float damage;           // 4 bytes
    public short state;            // 2 bytes (FighterState 枚举)
    public short shieldHP;         // 2 bytes
    public byte flags;             // 1 byte
    // bit 0: isFacingRight
    // bit 1: isGrounded
    // bit 2: isInvincible
    // bit 3-7: 预留
    public sbyte remainingJumps;   // 1 byte
    
    public void NetworkSerialize<T>(BufferSerializer<T> serializer) where T : IReaderWriter
    {
        serializer.SerializeValue(ref position);
        serializer.SerializeValue(ref velocity);
        serializer.SerializeValue(ref damage);
        serializer.SerializeValue(ref state);
        serializer.SerializeValue(ref shieldHP);
        serializer.SerializeValue(ref flags);
        serializer.SerializeValue(ref remainingJumps);
    }
}

// === 游戏事件（按需发送，可靠传输） ===
public struct GameEventData : INetworkSerializable
{
    public byte eventType;   // 0=PlayerJoined, 1=MatchStart, 2=MatchEnd, 3=Respawn, ...
    public int playerID;     // 关联的玩家 ID
    public float value;      // 附加数值（如比赛倒计时）
    
    public void NetworkSerialize<T>(BufferSerializer<T> serializer) where T : IReaderWriter
    {
        serializer.SerializeValue(ref eventType);
        serializer.SerializeValue(ref playerID);
        serializer.SerializeValue(ref value);
    }
}
```

### 5.4 改动前后对比

```
当前（单机版）：
  InputManager → 直接调用 → FighterController (Update: 逻辑+渲染)

联机版：
  ┌─ 本地模式：InputManager → 直接调用 → FighterController (不变)
  │
  └─ 网络模式：
       Client: InputManager → NetworkPlayerInput.SendRpc → ═══ UDP ═══→
                                                                    │
       Host:   ← UDP ═══ NetworkFighterState.ReceiveInput → FighterController_Server.FixedUpdate()
                                                                    │
               └─── UDP ───→ BroadcastStateClientRpc()
                                                                    │
       Client: ← UDP ═══ OnStateUpdate → ClientInterpolator → Fighter_Client.Render()
```

**关键设计**：本地模式和网络模式用同一套代码路径。切换模式只是把"输入来源"从本地改到网络 + 把"逻辑运行"从本地改到 Host。FighterController 本身跑的逻辑完全一样。

## 八、风险和注意事项

### 8.1 已知风险

| 风险 | 概率 | 影响 | 缓解方案 |
|------|------|------|---------|
| Unity Netcode 2.x API 变化 | 中 | 高 | 锁定大版本 `2.11.x`，不追新 |
| Physics2D 确定性 | 中 | 中 | 所有 Client 关物理，只在 Host 跑 |
| 4 人同屏 + 60fps 状态广播 | 低 | 中 | LAN 带宽完全够（~13KB/s），但注意序列化性能 |
| Host 同时跑逻辑+渲染的帧率 | 低 | 中 | Host 不需要额外开销，和单机一样 |

### 8.2 不做的事情

- ❌ **不做互联网对战**（需要 NAT 穿透、中继服务器、匹配系统，工程量翻 5 倍）
- ❌ **不做 Rollback Netcode**（毕业设计没必要，而且 10 倍复杂度）
- ❌ **不做断线重连**（LAN 聚会场景断了直接重开一局）
- ❌ **不做观战模式**（需要额外的状态同步路径，优先级低）

### 8.3 明确的边界

```
                    ┌─────────────────────┐
                    │    本方案覆盖范围      │
                    │  LAN 4人同屏对战      │
                    └─────────────────────┘
                              │
         ┌────────────────────┼────────────────────┐
         ▼                    ▼                    ▼
  不是这个             不是这个             不是这个
  ┌──────────┐    ┌──────────────┐    ┌──────────────┐
```

### 9.1 NetworkPlayerInput.cs（核心：客户端发输入）

```csharp
using Unity.Netcode;
using UnityEngine;

namespace SuperSmashLike.Network
{
    public class NetworkPlayerInput : NetworkBehaviour
    {
        private InputManager localInput;
        private PlayerInputData currentInput;

        private void Awake()
        {
            localInput = GetComponent<InputManager>();
        }

        private void Update()
        {
            if (!IsClient) return;

            // 打包输入
            currentInput = new PlayerInputData
            {
                moveInput = localInput.MoveInput,
                buttons = BuildButtonMask()
            };

            // RPC 发送给 Host（非可靠：丢帧就丢，下一帧覆盖）
            SendInputToServerRpc(currentInput);
        }

        private ushort BuildButtonMask()
        {
            ushort mask = 0;
            if (localInput.JumpPressed)  mask |= (1 << 0);
            if (localInput.AttackPressed) mask |= (1 << 1);
            if (localInput.SpecialPressed) mask |= (1 << 2);
            if (localInput.ShieldHeld)   mask |= (1 << 3);
            if (localInput.GrabPressed)  mask |= (1 << 4);
            if (localInput.TauntPressed) mask |= (1 << 5);
            return mask;
        }

        [Rpc(SendTo.Server, Delivery = RpcDelivery.Unreliable)]
        private void SendInputToServerRpc(PlayerInputData input)
        {
            // Host 端：将输入存储到对应的 FighterController_Server
            var serverCtrl = GetComponent<FighterController_Server>();
            if (serverCtrl != null)
                serverCtrl.ApplyRemoteInput(input);
        }
    }
}
```

### 9.3 ClientInterpolator.cs（Client 端插值渲染）

```csharp
using Unity.Netcode;
using UnityEngine;

namespace SuperSmashLike.Network
{
    /// <summary>
    /// Client 端渲染：收到 Host 的状态后做插值平滑。
    /// 不跑任何游戏逻辑，只做"看起来对"的渲染。
    /// </summary>
    public class ClientInterpolator : NetworkBehaviour
    {
        [Header("References")]
        public Animator animator;
        public Transform visualRoot;  // 角色模型根节点

        // 状态缓存（保留最近 3 帧）
        private struct TimedState
        {
            public FighterStateData state;
            public float timestamp;
        }
        private CircularBuffer<TimedState> stateBuffer = new(3);

        private void Update()
        {
            if (!IsClient) return;

            // 插值渲染：从缓存中取两帧做 Lerp
            if (stateBuffer.Count >= 2)
            {
                var prev = stateBuffer[0];
                var next = stateBuffer[1];
                float t = (Time.time - prev.timestamp) / (next.timestamp - prev.timestamp);
                t = Mathf.Clamp01(t);

                // 位置插值
                transform.position = Vector2.Lerp(prev.state.position, next.state.position, t);

                // 动画同步
                animator.SetInteger("State", next.state.state);
                animator.SetFloat("Speed", Mathf.Abs(next.state.velocity.x));
                animator.SetBool("IsGrounded", (next.state.flags & 0x02) != 0);

                // 朝向
                visualRoot.localScale = new Vector3(
                    (next.state.flags & 0x01) != 0 ? 1 : -1, 1, 1);
            }
        }

        // 由 NetworkFighterState.OnStateUpdateClientRpc 调用
        public void OnStateReceived(FighterStateData state)
        {
            stateBuffer.Add(new TimedState { state = state, timestamp = Time.time });
        }
    }
}
```

### 9.4 NetworkDiscovery.cs（LAN 广播发现）

```csharp
using System.Net;
using System.Net.Sockets;
using System.Text;
using UnityEngine;

namespace SuperSmashLike.Network
{
    /// <summary>
    /// LAN 发现：Host 监听广播，Client 发送扫描请求。
    /// UDP 广播到 255.255.255.255:47777
    /// </summary>
    public class NetworkDiscovery : MonoBehaviour
    {
        private UdpClient udpClient;
        private const int DiscoveryPort = 47777;

        // === Host 端：监听 ===
        public void StartHostDiscovery()
        {
            udpClient = new UdpClient(DiscoveryPort);
            udpClient.BeginReceive(OnReceive, null);
            Debug.Log("[Discovery] Host 开始监听 LAN 扫描请求");
        }

        private void OnReceive(IAsyncResult result)
        {
            IPEndPoint senderEndpoint = new(IPAddress.Any, 0);
            byte[] data = udpClient.EndReceive(result, ref senderEndpoint);
            string msg = Encoding.UTF8.GetString(data);

            if (msg == "SSLIKE_DISCOVER")
            {
                // 回复房间信息
                byte[] response = Encoding.UTF8.GetBytes(
                    $"SSLIKE_RESPONSE|{Application.productName}|{NetworkManager.Singleton.NetworkConfig.NetworkTransport.GetCurrentHostName()}");
                udpClient.Send(response, response.Length, senderEndpoint);
                Debug.Log($"[Discovery] 已响应 {senderEndpoint.Address} 的扫描");
            }

            // 继续监听
            udpClient.BeginReceive(OnReceive, null);
        }

        // === Client 端：扫描 ===
        public void ScanLAN()
        {
            udpClient = new UdpClient();
            udpClient.EnableBroadcast = true;

            byte[] request = Encoding.UTF8.GetBytes("SSLIKE_DISCOVER");
            udpClient.Send(request, request.Length, new IPEndPoint(IPAddress.Broadcast, DiscoveryPort));

            udpClient.BeginReceive(OnScanResponse, null);
            Debug.Log("[Discovery] 已广播 LAN 扫描请求");
        }

        public System.Action<string> OnRoomFound;  // 发现房间的回调

        private void OnScanResponse(IAsyncResult result)
        {
            IPEndPoint senderEndpoint = new(IPAddress.Any, 0);
            byte[] data = udpClient.EndReceive(result, ref senderEndpoint);
            string msg = Encoding.UTF8.GetString(data);

            if (msg.StartsWith("SSLIKE_RESPONSE"))
            {
                string roomName = msg.Split('|')[1];
                string hostName = msg.Split('|')[2];
                string ip = senderEndpoint.Address.ToString();
                OnRoomFound?.Invoke($"{roomName} @ {ip} ({hostName})");
                Debug.Log($"[Discovery] 发现房间: {roomName} ({ip})");
            }

            // 继续接收（等待更多响应）
            udpClient.BeginReceive(OnScanResponse, null);
        }

        private void OnDestroy()
        {
            udpClient?.Close();
        }
    }
}
```

> **一句话总结**：现在安心做单机版，只需要在代码里用注释/region 把"逻辑"和"渲染"分开标记。将来加网络时，整个方案就是"把逻辑搬到 Host 跑，Client 只负责收状态+插值显示"。LAN 场景延迟极低，不需要复杂的 rollback 技术。
