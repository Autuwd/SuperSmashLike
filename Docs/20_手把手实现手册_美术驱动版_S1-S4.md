## 阶段 2：S1-B 动画接入（纯 Animator 操作 + 参数对齐，零代码）

### 2.1 背景：代码到底在调什么（先懂再改）

代码侧（`FighterController.cs` / `FighterAnimator.cs`）只调用这些参数：

| 参数 | 类型 | 代码触发位置 | 说明 |
|------|------|--------------|------|
| `Speed` | Float | 每帧 | 移动速度绝对值 |
| `IsGrounded` | Bool | 每帧 | 是否着地 |
| `VerticalSpeed` | Float | 每帧 | 垂直速度 |
| `Damage` | Float | 受伤时 | 伤害值 |
| `State` | Int | 状态切换时 | **动画状态的唯一驱动源**，见下表 |
| `DeathTrigger` | Trigger | 死亡时 | 死亡触发 |

`State` 对应 `FighterState` 枚举值（`FighterState.cs`）：

| 值 | 状态 | 值 | 状态 |
|----|------|----|------|
| 0 | Idle | 7 | Knockback（击飞） |
| 1 | Run | 8 | Shield（举盾） |
| 2 | Jump | 9 | ShieldStun |
| 3 | Fall | 10 | Grab |
| 4 | Attack | 11 | Grabbed |
| 5 | Hit | 12 | Dead |
| 6 | Stun | 13 | FreeMove |

**当前 Animator 的问题（预检 0.3 警告的根源）**：controller 里是 6 个旧参数（Speed/IsGrounded/VerticalSpeed/**AttackTrigger/DamageTrigger/DeadBool**），缺 `State`/`Damage`/`DeathTrigger`——所以代码每次调用都警告，且动画永远不切换（因为旧触发器和代码对不上）。修复 = 参数对齐 + 全部转换改用 `State` 驱动。

### 2.2 修正 Animator 参数（2 分钟）

打开 `FighterAnimator.controller`（Animator 窗口）→ Parameters 面板：

1. **删除** 3 个废弃参数：`AttackTrigger`、`DamageTrigger`、`DeadBool`（选中 → 右键 → Delete）
2. **新增** 3 个参数：`Damage`（Float）、`State`（Int）、`DeathTrigger`（Trigger）
3. 最终参数面板应有 6 个：`Speed(F)` `IsGrounded(B)` `VerticalSpeed(F)` `Damage(F)` `State(I)` `DeathTrigger(T)`

### 2.3 挂动画 Clip（Project 窗口搜索关键字，拖进 Motion 槽）

动画在 `Assets/Synty/PolygonFantasyRivals/AnimationSwordCombat/Samples/Animations/` 和 `Assets/Synty/PolygonFantasyRivals/Polygon/` 下。**用 Project 窗口搜索框搜名字**（搜不到就搜关键字，下面给了备选）：

### 2.4 全部用 AnyState 转换（核心手法：10 分钟，一次配完）

**手法**：状态机里只有 8 个状态，用 **10 条 AnyState → 状态** 的转换，每条条件 = `State == n`。动画切换完全由代码设置的 `State` 值决定，不需要改一行代码。

每个状态逐个操作（以 Idle 为例）：

1. 右键 Idle 状态 → Make Transition，**从 "Any State"** 拉线到 Idle（鼠标从 Any State 拖到 Idle）
2. 点选该转换，Inspector 设置：
   - **Has Exit Time：取消勾选**（立刻切换）
   - **Transition Duration：0.05**（轻微过渡防闪烁）
   - **Conditions：+ 添加 → `State` `Equals` `0`**
3. 照做其余 9 条（值见下表）：

| 转换 | 条件 | | 转换 | 条件 |
|------|------|-|------|------|
| AnyState → Idle | State == 0 | | AnyState → Shield | State == 8 |
| AnyState → Run | State == 1 | | AnyState → Knockback | State == 7 |
| AnyState → Jump | State == 2 | | AnyState → Dead | State == 12 |
| AnyState → Fall | State == 3 | | AnyState → Stun | State == 6 |
| AnyState → Attack | State == 4 | | AnyState → FreeMove | State == 13 |

> 条件互斥（State 同一时刻只有一个值），转换之间不会打架。**不要给 Jump/Fall/Attack 加"离开状态"的转换**——回 Idle 由代码把 State 设回 0 触发 AnyState → Idle。
> 状态优先级：死/击飞（Knockback=7、Dead=12）的转换在前，其余在后——虽然条件互斥，保持这个顺序更清晰。

- [ ] 击飞落地后能正常回 Idle（FreeMove → Idle）

## 阶段 3：S1-C 手感调优（改代码 + 调资产参数）

### 3.1 面朝方向翻转（新增功能：目前代码没有朝向逻辑）

大乱斗式对战中面朝对手是刚需。当前代码**完全没有**翻转逻辑（实测确认）。在 `FighterController.cs` 加：

**Step 1**：类内加字段（放在 `public FighterData data;` 附近）：

```csharp
private bool isFacingRight = true;   // 当前朝向
```

**Step 2**：`Update()` 末尾（`SetAnimatorParameters()` 调用之后）加：

```csharp
// 面向对手（仅在可自由行动时更新朝向）
bool canTurn = state == FighterState.Idle || state == FighterState.Run || state == FighterState.FreeMove;
if (canTurn)
{
    Transform target = (MatchManager.Instance != null && MatchManager.Instance.Players != null)
        ? MatchManager.Instance.GetOpponentOf(this)
        : null;
    if (target != null)
    {
        bool faceRight = target.position.x > transform.position.x;
        if (faceRight != isFacingRight)
        {
            isFacingRight = faceRight;
            transform.rotation = Quaternion.Euler(0f, isFacingRight ? 0f : 180f, 0f); // 3D 模型用 Y 旋转
        }
    }
}
```

> ⚠️ 若 `MatchManager` 没有公开 `GetOpponentOf(FighterController)` 方法：改用 `MatchManager.Instance.Players` 遍历（`FighterController` 数组），找 `!= this` 的那个即可。**以现场实际 API 为准**，只保留能编译的部分。
> 说明：转 180° 后模型前后颠倒（3D 模型背面），若视觉上不理想，把模型子物体 Scale.x 改为 -1 抵消（美术细节，可后调）。

### 3.2 平台跳跃手感（可选的 3 个小增强）

打开 `FighterController.cs`，逐个加入（每段都是完整可粘贴的）：

**① 快速下落（按 ↓ 更快落地）**——在 `Update()` 移动逻辑后加：

```csharp
// 快速下落：下落中按下 S/↓ 加速
bool fastFallHeld = playerID == 0
    ? GameInput.Instance.P1Move.y < -0.5f
    : GameInput.Instance.P2Move.y < -0.5f;
if (state == FighterState.Fall && fastFallHeld && rb.velocity.y < -4f)
{
    rb.velocity = new Vector2(rb.velocity.x, Mathf.Max(rb.velocity.y, -data.fallSpeed * 1.6f));
}
```

> ⚠️ `GameInput.Instance.P1Move` 等字段名**以现场 InputManager/GameInput 脚本为准**（可能是 `Player1Move`/`InputManager.Instance.MoveP1` 之类），先看该文件再改。

**② 按跳跃缓冲（快落地时按跳跃不丢）**——类内加字段：

```csharp
private float jumpBufferTimer = 0f;   // 跳跃缓冲计时
```

`Update()` 内、处理跳跃的代码块**之前**加：

```csharp
// 记录最近 0.1 秒内的跳跃意图
if (playerID == 0 ? GameInput.Instance.P1JumpPressed : GameInput.Instance.P2JumpPressed)
    jumpBufferTimer = 0.1f;
else
    jumpBufferTimer -= Time.deltaTime;
```

然后把**原有的跳跃触发条件** `if (jumpPressed && grounded)` 改为：

```csharp
if (jumpBufferTimer > 0f && grounded)
{
    jumpBufferTimer = 0f;   // 消耗缓冲
    // …原有跳跃代码（JumpState 切换、rb.velocity 设置）保持不变…
}
```

**③ 土狼时间（离开平台边缘 0.1 秒内仍可跳）**——类内加字段：

```csharp
private float coyoteTimer = 0f;
```

`Update()` 内加：

```csharp
// 土狼时间：着地时刷新，离地后短暂保留
if (grounded) coyoteTimer = 0.1f;
else coyoteTimer -= Time.deltaTime;
```

同样把跳跃条件改为 `if (jumpBufferTimer > 0f && (grounded || coyoteTimer > 0f))`。

> 若改完编译报错（字段名不匹配），**以现场代码为准微调名字**；若不想动代码，跳过 3.2 的②③ 不影响主线。

## 阶段 4：S2 战斗美术（攻击动画 + 命中特效）

### 4.1 先修一个自伤 Bug：Hitbox.owner 未赋值（必修）

`Hitbox.cs` 的 `OnTriggerEnter2D` 里用 `hurtbox.owner != owner` 判断"不打自己人"，但代码里**没有任何地方给 Hitbox.owner 赋值**（实测确认）→ 攻击会打到自己。

在 `FighterController.cs` 的 `Awake()`（现有 `hurtbox = GetComponentInChildren<Hurtbox>();` 那行**后面**）加：

```csharp
// 修复：给所有 Hitbox 指定所有者，防止自伤
var hitboxes = GetComponentsInChildren<Hitbox>(true);
foreach (var hb in hitboxes) hb.owner = this;
```

> 若 `Hitbox.owner` 是 `private`：把 `Hitbox.cs` 里 `[HideInInspector] public FighterController owner;` 改为 public（如果原来是 `[HideInInspector]` 就保持，只改访问级别）。

### 4.2 给角色加 Hitbox（场景/预制体操作 + 动画事件）

1. 打开 `Fighter_Base.prefab` 编辑模式 → 选中 **Visual**（Animator 所在物体）→ 右键 → Create Empty → 命名 `Hitbox`
2. 在 Hitbox 上加：`BoxCollider2D`（勾 Is Trigger）+ `Hitbox` 脚本
3. 配置：
   - Hitbox 脚本的 `attackData`：拖入对应攻击的 AttackData 资产（如 `AD_LightAttack`，在 `Assets/_Game/Data/` 下）
   - Collider 尺寸：`Size = (0.8, 0.6)`，Position 调到头前方（先 (0.4, 0.1, 0) 再 Play 微调）
   - **取消勾选 Hitbox 物体**（默认关闭，等动画事件开启）
4. 加动画事件（关键：事件能调用的组件必须在 **Animator 所在物体**上，所以 Hitbox 挂在 Visual 下）：
   - Window → Animation → Animation 窗口
   - 选中 Visual → Animator 状态机里点 **Attack** 状态（已挂挥剑 clip）
   - 时间轴拖到**挥剑刚挥出**那帧（约 30% 处）→ 点 Add Event → 函数选 `Activate` → 目标组件选 Hitbox
   - 拖到**挥剑结束**那帧（约 85%）→ Add Event → 函数选 `Deactivate` → Hitbox
   - **重复 4 次**：每次做同一条攻击的动画事件时，Animator 状态**不能同时有多个状态在播同一个 clip 的同一帧**（事件一次只作用于当前选中的状态；把两个角色的 Attack 状态都配上）

> 攻击流程（代码已实现，你只配事件）：Play 攻击 → 动画事件 `Activate` → Hitbox 开启 → 碰到敌人 Hurtbox → 计算伤害+击飞+Hitstop → 动画事件 `Deactivate` → Hitbox 关闭。动画事件函数名必须是 `Activate`/`Deactivate`（`Hitbox.cs` 里已有）。

### 4.3 命中特效（改 3 行代码 + 资产拖拽）

**Step 1**：`Hitbox.cs` 的 `OnTriggerEnter2D` 里、造成伤害的代码**之后**加：

```csharp
// 命中特效（在 AttackData 资产里配）
if (attackData.hitEffectPrefab != null)
{
```

## 阶段 6：S4 多人 HUD（UI 倒计时 + 双人输入修复）

### 6.1 先修"双人同输入"Bug（必修，根因实测确认）

**现象**：两个角色都同时响应同一键盘——因为 `InputManager` 克隆了输入资产但**没有设置 `bindingMask`**，两套 PlayerInput 都在听"全部键盘设备"。

**修复**：打开 `InputManager.cs`（或现场同名脚本），在 `Awake()` 里 `LoadFromJson`（克隆资产）**之后**加：

```csharp
// 按玩家编号隔离输入绑定（P1=KeyboardP1 组，P2=KeyboardP2 组）
int pid = GetComponent<FighterController>() != null ? GetComponent<FighterController>().playerID : 0;
string group = pid == 0 ? "KeyboardP1" : pid == 1 ? "KeyboardP2" : "Gamepad";
runtimeActions.bindingMask = InputBinding.MaskByGroup(group);
```

> 需要 `using UnityEngine.InputSystem;`（文件里通常已有）。分组名 `KeyboardP1`/`KeyboardP2`/`Gamepad` 是 `Controls.inputactions` 里**实测存在的 control scheme**，直接可用。
> 效果：P1 只认 WASD+JKL 区，P2 只认方向键+小键盘区，互不干扰。手柄玩家把 playerID 改成 2 走 Gamepad 组（进阶玩法，可后做）。

### 6.2 HUD 双方案（A 用 Synty 现成 HUD；B 纯代码必然成功）

Synty HUD 包 `Assets/Synty/InterfaceFantasyWarriorHUD/Prefabs/` 结构（实测）：子目录 `Player_Health_Equipment/`、`Timed/`、`_PreMadeHUDs/`、`ActionBars/`、`Compass_Minimap/` 等，内部百分比文本节点实测命名为 **`LeftPct` / `RightPct`**（名字已验证）。

## 🧠 面试联动（本次踩到的真实知识点，答法沉淀）

1. **Q「Animator 参数与代码脱钩」**：动画参数应由**单一驱动源**（如 int State）统一控制，不要给每个动画一个独立 Trigger——Trigger 多则状态机爆炸、代码和资产极易脱钩（本次 `AttackTrigger` 等 3 个废弃参数就是教训）。**一句话速记**：状态用 Int 枚举、转换用 AnyState+Equals 条件，代码侧永不直接引用动画 clip 名。
2. **Q「Animation Event 的调用目标」**：Animation Event 只能调用 **Animator 所在 GameObject 上**的组件方法（子物体不行）→ Hitbox 必须挂在 Visual（Animator 所在物体）下。
3. **Q「自伤 Bug 的成因」**：伤害判定 `hurtbox.owner != owner` 的 owner 从未赋值 → null 判断漏洞。**速记**：判定逻辑字段必须在 Awake 全量初始化（`GetComponentsInChildren`），否则条件判断形同虚设。
4. **Q「双人同输入的根因」**：克隆 `InputActionAsset` 后必须 `bindingMask = MaskByGroup(scheme)` 隔离绑定；只克隆不隔离 = 两组 PlayerInput 同时响应同一设备。**速记**：Input System 的 bindingMask 是"一人一套绑定"的唯一闸门。
5. **Q「Hitstop（顿帧）在哪实现」**：`AttackData.hitstopDuration` + `Time.timeScale` 短暂归零——顿帧时 Animator 用 `Update Mode = Unscaled Time` 或事件错开，避免打击感丢失（本项目已实现，复习 `Docs/13` 对应题号）。
