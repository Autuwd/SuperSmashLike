# 项目实施计划

---

## 一、总体设计哲学

### 自底向上的构建策略

本项目采用 **数据驱动 + 分层构建** 的开发方式，核心原则：

```
ScriptableObject 数据定义 (Data Layer)
    ↓
基类/工具类 (Core/Foundation)
    ↓
业务逻辑子系统 (Character/Combat/Stage)
    ↓
管理器协调层 (Managers)
    ↓
UI 表现层 + 场景装配 (Unity Editor)
```

**先设计数据 → 再实现逻辑基类 → 最后派生具体功能。** 目前代码层已全部完成，现阶段的实施顺序就是：**ScriptableObject 资产创建 → 预制体装配 → 动画绑定 → 场景搭建 → UI 构建 → 多人与内容扩展**。

## 二、Phase 0：根基 — 创建 ScriptableObject 资产实例

> **为什么先做这一步？** 所有代码都依赖 SO 数据。没有 SO 资产，任何角色/舞台都无法运行。

### 2.1 创建 GameSettings 资产

| 步骤 | 操作 |
|------|------|
| 1 | 在 `Assets/_Game/ScriptableObjects/GameModes/` 右键 → Create → SuperSmashLike → GameSettings |
| 2 | 命名：`GS_Default.asset` |
| 3 | 配置默认值（比赛模式=时间制 3分钟/命数制 3命、重生无敌3秒、护盾参数等） |

### 2.2 创建 FighterData 资产

| 步骤 | 操作 |
|------|------|
| 1 | 在 `Assets/_Game/ScriptableObjects/Characters/` 右键 → Create → SuperSmashLike → FighterData |
| 2 | 为每个角色创建资产：`FD_Knight.asset`, `FD_Archer.asset`, `FD_Mage.asset`, `FD_Barbarian.asset` |
| 3 | 配置基础属性（体重/速度/跳跃力，每个角色不同） |
| 4 | 配置攻击数据数组（18种攻击类型各自的伤害/角度/击飞值/帧数据） |

### 2.3 创建 StageData 资产

| 步骤 | 操作 |
|------|------|
| 1 | 在 `Assets/_Game/ScriptableObjects/Stages/` 右键 → Create → SuperSmashLike → StageData |
| 2 | 命名：`SD_Arena.asset` |
| 3 | 配置摄像机边界、BlastZone 偏移、出生点、环境光、BGM |

**产出检查**：Project 窗口中能看到 `FD_Knight.asset` 等文件，Inspector 可编辑所有数值。

## 三、Phase 1：原型构建（可对战 Demo）

### 3.1 角色预制体装配

> **构建思路：从上往下挂载组件，GameObject 层级结构如下**

```
Fighter (GameObject)
├── SpriteRenderer / SkinnedMeshRenderer  (角色模型)
├── Rigidbody2D (或 Rigidbody)            (物理)
├── Collider2D                            (碰撞体)
├── Animator                              (动画控制器，引用下一步创建的 controller)
├── FighterController.cs                  (主控制器，引用 FD_xxx.asset)
├── FighterStateMachine.cs                (状态机，自动关联)
├── PlayerInput                           (Unity Input System 组件)
│   └── InputActionAsset                  (引用 Controls.inputactions)
├── Hitbox (多个子物体)                    (攻击判定框)
│   ├── Hitbox_Jab
│   ├── Hitbox_SmashSide
│   ├── Hitbox_AerialNeutral
│   └── ...
└── Hurtbox (子物体)                      (受击判定框)
```

#### 3.1.1 创建 Animator Controller

| 步骤 | 操作 |
|------|------|
| 1 | 在 `Assets/_Game/Animations/` 右键 → Create → Animator Controller，命名 `FighterAnimator` |
| 2 | 创建参数：`State`(int)、`Speed`(float)、`Direction`(float)、`InAir`(bool) |
| 3 | 创建状态机映射（每个 FighterState 对应一个动画状态） |

**状态-动画映射表：**

| FighterState | 动画状态名 | BlendTree? |
|-------------|-----------|-----------|
| Idle | `Idle` | 否（单动画） |
| Run | `Run` | 是（Blend by Speed） |
| Jump | `Jump` | 否 |
| Fall | `Fall` | 否 |
| Attack | `Attack_Jab` / `Attack_SmashSide` / 等 | 否（每个攻击类型独立） |
| Hit | `Hit` | 否 |
| Knockback | `Knockback` | 否 |
| Shield | `Shield` | 否 |
| Dead | `Dead` | 否 |

**FighterController.Update() 中每帧同步：**
```csharp
animator.SetInteger("State", (int)stateMachine.CurrentState);
animator.SetFloat("Speed", currentSpeed);
animator.SetBool("InAir", !isGrounded);
```

#### 3.1.2 创建预制体

| 步骤 | 操作 |
|------|------|
| 1 | 在场景中搭建 Fighter 的 GameObject 层级，挂载好所有组件 |
| 2 | 拖入 `Assets/_Game/Prefabs/Fighters/` → 创建 Prefab Variant 给每个角色 |
| 3 | 每个 Variant 引用不同的 `FighterData` 资产和对应模型 |

│   ├── BoxCollider2D (isTrigger 按需切换)

### 3.3 场景搭建

### 3.4 动画事件绑定

> Animator Controller 中的 Animation Clip 需要在特定帧触发 Hitbox 激活。

- 在 Animation Clip 中添加 Animation Event：
  - `OnHitboxActivate(string boxName)` — 判定框启用
  - `OnHitboxDeactivate()` — 判定框关闭
  - `OnAttackEnd()` — 攻击结束通知 FighterController

**当前 FighterController 中的对应方法：**
```csharp
// FighterController.cs 中已有
public void OnHitboxActivate(string boxName) { ... }
public void OnHitboxDeactivate() { ... }
public void OnAttackEnd() { ... }
```

## 四、Phase 2：UI 系统（完整游戏流程）

### 4.1 UI 架构设计

```
UI 管理器采用面板栈 (Panel Stack) 模式：
UIManager (单例)
├── Panel_CharacterSelect
├── Panel_HUD
├── Panel_Pause
└── Panel_Result
```

#### 4.1.1 UIManager 基类设计

```csharp
// 位置：Assets/_Game/Scripts/UI/UIManager.cs
public class UIManager : MonoBehaviour
{
    public static UIManager Instance { get; private set; }
    
    [SerializeField] private GameObject[] panels;   // 所有UI面板
    private Stack<GameObject> panelStack = new();    // 面板栈
    
    public void PushPanel(GameObject panel) { ... }  // 打开面板（压栈）
    public void PopPanel() { ... }                    // 返回上一面板（出栈）
    public void SwitchToPanel(GameObject panel) { ... } // 替换当前面板
}
```

#### 4.1.2 UI 面板设计

每个 Panel 是一个独立的 prefab，使用 Unity Canvas + 子 GameObject 构建：

| Panel | 内容 |
|-------|------|
| **CharacterSelectPanel** | 角色网格(4列) × 玩家槽(4个) → 确认按钮 → 开始比赛 |
| **HUDPanel** | 每个玩家的伤害百分比数字 + 头像 + 命数指示器 + 倒计时 |
| **PausePanel** | 继续 / 返回选人 / 退出游戏 |
| **ResultPanel** | 排名(1st~4th) + 击杀数/受伤数 + 再来一局 / 返回标题 |

### 4.2 场景流程

```
BootScene (启动/加载)
    ↓ 加载完成
TitleScene (标题画面)
    ↓ 按任意键
CharacterSelectScene (选人界面)
    ↓ 所有玩家锁定 → 场景加载
BattleScene (对战)
    ↓ 比赛结束 → 延迟1.5s
ResultScene (结算)
    ├── 再来一局 → BattleScene (重新加载)
    └── 返回标题 → TitleScene
```

**MatchManager 中已实现的场景流程接口：**
```csharp
MatchManager 的 OnMatchEnd() 方法 → 调用 SceneManager.LoadScene("ResultScene")
```

## 八、设计原则总结

### 基类优先 vs 功能优先

本项目采用 **数据层 → 工具层 → 业务层 → 表现层** 的构建顺序：

1. **ScriptableObject 资产** — 先于一切，因为它们是所有数据的来源
2. **基类/工具类**（已全部完成）— `FighterController`、`DamageSystem`、`ObjectPooler` 等
3. **具体功能** — 通过装配预制体、挂载组件、绑定数据来实现功能
4. **迭代调优** — 在 Play 模式中调整 SO 数值，无需修改代码

**核心原则：**

| 原则 | 说明 |
|------|------|
| **数据驱动** | 所有可调参数放在 SO 中，代码不硬编码数值 |
| **组合优于继承** | 功能通过组件组合实现（FighterController + StateMachine + Hitbox），而非深继承链 |
| **单一职责** | 每个脚本只做一件事（Hitbox 只管判定，DamageSystem 只管计算） |
| **接口隔离** | 子系统之间通过明确的方法调用通信，不直接操作对方内部状态 |
| **分层依赖** | UI → Manager → Gameplay → Data → Input，上层依赖下层，下层不依赖上层 |
